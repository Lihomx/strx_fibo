# STRX Fibo Scanner – 系统分析与升级机会

---

## 📊 概览
当前代码库由 **Streamlit** Web 应用 (`app.py`) 以及基于 **JSON 文件** 的存储层 (`storage.py`) 组成。辅助模块（`page_*.py`、`cloud_sync.py` 等）提供页面、云同步及其他工具函数。系统可正常运行，但在以下方面仍有提升空间，可增强 **用户体验**、**性能**、**可维护性**、**安全性** 以及 **未来特性可扩展性**。

---

## 🔧 1. UI / UX 改进
| 区域 | 当前状态 | 建议升级 | 价值 |
|------|----------|----------|------|
| 主题 | 仅浅色、手写 CSS | 添加 **暗色模式切换**（利用 Streamlit 的 `st.experimental_set_query_params` + CSS 变量） | 减轻眼睛疲劳，提升现代感 |
| 布局 | 侧边栏宽度固定，移动端通过 CSS hack 适配 | 重构为 **响应式布局**，使用 `st.columns`、`st.tabs`，并可提供 **网格视图** 给自选列表 | 移动端体验更清晰，导航更便捷 |
| 动画 | 没有微交互 | 为按钮、加载指示器等加入 CSS 过渡效果 | UI 更活泼，提升感知速度 |
| 字体 | 使用系统默认字体 | 引入谷歌字体（如 `Inter`、`Roboto`），统一排版比例 | 高级视觉感受 |
| 可访问性 | 缺少 ARIA 标签，配色对比度未检查 | 添加 `aria-label`，确保符合 WCAG 对比度，支持键盘操作 | 包容性设计 |
| 品牌 | Logo 文本硬编码 | 提供 **可配置的品牌块**（图片、标题），从 `storage.CONFIG` 读取 | 支持白标化部署 |

## ⚡ 2. 性能与可扩展性
| 区域 | 问题 | 优化方案 | 实现提示 |
|------|------|----------|----------|
| 数据加载 | 每次请求都读取完整 `data_allresults.json`（最多 5k 条） | 使用 **分页加载** 与 **惰性加载**（如 `st.experimental_data_editor`、`AgGrid`） | 根据 UI 页码切片返回 |
| 文件 I/O | 同步读写阻塞主线程 | 改为 **线程池异步 I/O**（`concurrent.futures.ThreadPoolExecutor`）用于备份等耗时操作 | 将 `_load/_save` 包装为 `run_in_executor` |
| 云同步 | 在 `save_scan` 中直接调用 `_async_push`，可能未处理失败重试 | 引入 **重试/退避** 与 **本地队列**（SQLite 或持久化列表）存放未成功的推送 | 可靠的离线同步 |
| 快照清理 | 每次保存时线性遍历 `scan_snapshots` 文件夹 | 维护 **时间戳最大堆** 或记录 **manifest**，快速裁剪 | 降低文件系统开销 |
| CSS 注入 | 大段内联 CSS 放在 `app.py` | 将 CSS 抽离至 **独立静态文件**，使用 `st.components.v1.html` 加载 | 代码更整洁，便于主题切换 |

## 🧹 3. 代码质量与可维护性
| 关注点 | 当前情况 | 建议 |
|----------|----------|------|
| 类型提示 | 部分函数缺失 `->` 注解 | 使用 **`mypy` 严格模式** 检查并补全类型提示 |
| 日志 | 没有结构化日志 | 添加 **logging 包装器**（`logging.getLogger(__name__)`），输出 JSON 结构日志记录错误与同步事件 |
| 文档 | Docstring 较少 | 采用 **Google/NumPy** 风格文档，使用 **Sphinx** 生成 API 文档 |
| 单元测试 | 无自动化测试 | 编写 **pytest** 测试覆盖存储操作、收藏夹增删改查、云同步桩代码 |
| 依赖管理 | 隐式 `import streamlit as st` 等 | 添加 **`requirements.txt`** 并锁定版本，考虑使用 `uv` 或 `poetry` 管理依赖 |
| 重复代码 | 备份逻辑在多个位置出现 | 抽象为 **`backup.py`** 模块，提供 `create_backup`、`prune_backups` 等函数 |
| 魔法数字 | 如 `_MAX_ALLRES = 5000` 硬编码 | 移动到 **`config.py`**，并在 UI 设置中暴露给用户 |

## 🔐 4. 安全性提升
| 风险点 | 当前实现 | 改进措施 |
|--------|----------|----------|
| 密码存储 | 明文密码存于 `st.secrets`，使用 HMAC 验证 | 对登录失败次数进行 **限流/退避**（`time.sleep`） |
| Token 泄露 | 登录 token 通过查询字符串 `_t` 传递 | 改为 **会话存储** 或 HttpOnly Cookie，登录后立即清除 URL 参数 |
| Secrets 曝露 | `st.secrets` 可能包含 API Key | 启动时检查必填项，并在日志中 **掩码** 关键信息 |
| 输入校验 | 收藏备注字段接受任意字符串 | 对输入进行 **HTML 转义**、长度限制，防止 XSS |
| 云同步认证 | 未看到显式认证 | 使用 **OAuth2** 或签名 URL 与 Supabase 交互，定期轮换 token |
