## 🔥 一、高优先级 — 快速见效（1-2 小时/项）

### 1.1 ⚠️ `page_schedule.py` 引用崩坏修复
- **问题**：`page_schedule.py` 导入了不存在的 `core.supabase_client` 和 `core.scheduler` 模块，但未在 `app.py` 路由中注册，直接访问会报 `ModuleNotFoundError`
- **方案**：要么删除此文件，要么重写为使用当前 `storage.py` + `scheduler.py` 的版本
- **影响**：代码整洁度 + 避免维护混淆

### 1.2 🔐 侧边栏品牌 Logo 硬编码颜色
- **问题**：`app.py` 第 234 行 `color:#111` 在暗色模式下不可见
- **方案**：改为 `color:var(--text-color, #111)`
- **影响**：暗色模式视觉完整性

### 1.3 📈 `page_chartink.py` 暗色模式未适配
- **问题**：`_stat_card()` 函数使用硬编码浅色背景（`#eff6ff`, `#f0fdf4` 等），`_render_details()` 表格同样使用 `#f0fdf4`、`#fff7f7` 等浅色固定值
- **方案**：改用 `rgba()` 半透明 + CSS 变量
- **影响**：4H Breakout 页面暗色模式可用

### 1.4 🧹 清理残留文件
- **文件**：`_recover_zip/`、`strx_fibo-main (2).zip`、`daemon.log`、`secrets.toml`（不应提交到仓库）
- **方案**：添加到 `.gitignore` 并从仓库删除
- **影响**：仓库安全 + 整洁

### 1.5 📱 `importlib.reload()` 移除
- **问题**：`app.py` 对所有 12 个模块执行 `importlib.reload()`，每次页面加载强制重加载整个模块树
- **方案**：删除所有 `reload()` 调用（Streamlit Cloud 自动检测文件变更并 rerun）
- **影响**：页面加载提速 ~200ms，减少内存占用

## ⚡ 二、性能与扫描引擎升级

### 2.1 🚀 扫描数据本地缓存（减少重复请求）
- **问题**：每次扫描同一品种都重新请求网络数据，即使数据未过期
- **方案**：在 `scanner.py` 中引入带 TTL 的内存缓存（如 `@st.cache_data(ttl=300)`），同一品种 5 分钟内不重复拉取
- **节省**：批量扫描中若同品种跨页面使用，避免重复网络请求
- **工程量**：⭐⭐

### 2.2 📊 `data_allresults.json` 分片存储
- **问题**：当前 `data_allresults.json` 已达 **794KB**，每次读写都是全量 JSON 解析
- **方案**：按扫描日期分片（如 `results_2026-07-07.json`），加载时只读最近 N 天
- **影响**：I/O 性能提升 5-10x，尤其在 Streamlit Cloud 的临时磁盘上
- **工程量**：⭐⭐⭐

### 2.3 🔄 `_flush_rows` 竞态条件修复
- **问题**：`scanner.py` 第 694-715 行的 `_flush_rows()` 在多线程环境下直接读写 JSON 文件，无文件锁保护，可能导致数据丢失
- **方案**：使用 `threading.Lock` 包裹文件读写操作（或改用 `fcntl.flock`）
- **工程量**：⭐

## 🛡️ 四、安全与稳定性

### 4.1 🔑 Token 安全加固
- **问题**：登录 token（`_t` 参数）为 HMAC 哈希前 32 位，长期有效且暴露在 URL 中
- **方案**：改为带过期时间的 JWT（或 HMAC + 时间戳），过期后需重新登录
- **工程量**：⭐⭐

### 4.2 🛡️ Secrets 文件安全
- **问题**：`secrets.toml` 存在于工作目录且未被 `.gitignore` 排除
- **方案**：立即添加到 `.gitignore`，若已推送则从 Git 历史中清除
- **工程量**：⭐

### 4.3 📝 结构化日志系统
- **问题**：当前只有 `logger.debug/warning`，无标准输出格式，生产环境排障困难
- **方案**：配置 `logging.basicConfig` 为 JSON 格式，添加请求 ID 跟踪
- **工程量**：⭐⭐

## 📡 五、数据源与扫描策略

### 5.1 ⏱️ 增加 4H / 1H 时间框架
- **描述**：当前仅支持 Daily/Weekly/Monthly 三个框架，增加 4H 和 1H 短周期 Fibo 检测
- **实现**：在 `assets.py` 的 `TIMEFRAMES` 字典中添加对应配置，扫描引擎已兼容
- **价值**：日内交易者可获得更及时的信号
- **工程量**：⭐⭐

### 5.2 📊 RSI / MACD 辅助指标叠加
- **描述**：在扫描结果中额外显示 RSI(14) 和 MACD 状态，帮助确认 Fibo 信号有效性
- **实现**：在 `compute_fibo()` 返回值中添加 RSI/MACD 字段
- **价值**：提高信号质量，减少假信号
- **工程量**：⭐⭐

### 5.3 🔔 价格目标追踪（TP/SL 计算）
- **描述**：当品种进入黄金区间时，自动计算 Fibonacci 扩展位（1.0、1.272、1.618）作为止盈目标
- **实现**：在 Fibo 计算结果中添加 `targets` 字段
- **工程量**：⭐⭐
